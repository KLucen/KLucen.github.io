上个月我发过一篇 [《深入理解 AI Agent：设计原理与工程实践》章节精读笔记](https://klucen.cn/posts/66321874.html)。那篇是想给"想快速了解 Agent 到底在讲什么"的人一份简单的总结性文档，看完能知道这本书大致说了什么。但也仅此而已。

而这次开源的仓库是另一种东西。它的用法不是"替你把书读了"，而是**让你带着问题去读原文**：

> **[KLucen/ai-agent-book-note](https://github.com/KLucen/ai-agent-book-note)**（Apache-2.0）

具体怎么用：`内容精读/` 里每个小节的开头都有一组从正文里长出来的引导问题，先看问题，再去读原书对应段落，读完回来对照"读后小结"和"原文论证"。读的时候有想法、有疑问，就写进 `QuickNote/`。**你也可以先看看我在里面随手记下的感悟和不明白的地方，再翻到 `DeepReadNote/`，看这些答案是不是对你也一样有帮助。**

原书是 [bojieli/ai-agent-book](https://github.com/bojieli/ai-agent-book)，李博杰著，正文、编译版 PDF、每章配套代码全部开源（Apache-2.0）。我这份是**非官方**的个人精读笔记，不打算当原书的替代品或者翻译，它更像一份"这本书我到底是怎么读的"的完整记录。

## 里面有什么

```
Agent Book/
├─ 00-阅读地图.md      全书导航：核心公式、阅读路径、进度总表
├─ 01-精读笔记规范.md  模板与写作纪律（想复用这套方法看这份）
├─ 02-全书术语表.md    跨章术语总表，每个术语只在首见章给权威定义
├─ images/             原书插图副本，供笔记引用
├─ 内容精读/           每章"读"：逐节深析
├─ 实验解读/           每章"做"：实验逐条解读 + 动手记录区
├─ 思考题引导/         每章"考"：题目原文 + 提示思路 + 自答留白
├─ QuickNote/          我自己写的读书随笔，原始记录
└─ DeepReadNote/       AI 对我的随笔的回应与补充
```

三个分册对应三种读法：**读**原书、**做**实验、**考**自己。

`内容精读/` 里每个小节都是同一个四段式，这是我用得最顺的部分：

1. **带着这些问题阅读本节**——问题是从该小节正文里长出来的，不是通用模板；
2. **读后小结**——结论层，要覆盖该节全部要点，不写空话；
3. **原文论证**——原书证据，逐字引用并给出处锚点；
4. **取舍与延伸**——工程取舍、跨章关联。

`实验解读/` 每个实验给「目的 / 设计 / 关键结论」，后面留一张**动手记录区**的空白表，等我复现完自己填。`思考题引导/` 只给提示思路、不剧透答案，答案在原书的 `reference-answers.md` 里，先自答再看。

## 为什么我推荐从「问题引导」读起

这份笔记里我最想推的用法，就是先看 `内容精读/` 里那组引导问题，带着它们去读原书。

说实话一开始agent提的问题真的很差，因为在规范文档里面我也做了几次的修改，包括：

- **引导问题规则**：必须源自该小节正文实际展开的内容，正文没强调的点不许问；读完该小节应能直接回答并覆盖要点
- **小结深度规则**：「读后小结」须按原文充实——保留关键定义、分类对比、机制/流程链、书中数字与案例，原则是「不看原文也能从小结复述该节内容」

在现在这个规范下，我觉得阅读体验很不错了。大部分问题确实能把我按在"带着脑子读"的状态里，而不是眼睛扫过去、脑子没跟上；读完之后它给的小结也有分寸，该有的定义、对比、数字和案例都在，不至于浅到只剩一句正确的废话。

另一个我回过神来才觉得有用的设计：**笔记里引用到的原书图都留了一份副本，每张图下面还配了一句基于原文的解读**。不然过几个月再回来翻，看到个 `fig2-3` 只会想"这图当初是想说明啥来着"。

## 我最想推荐的是 QuickNote 和 DeepReadNote

读书的损耗主要发生在两处：读的时候没有焦点，读完没有反馈。引导问题管前一个，DeepReadNote 管后一个。

第 1 章读完，我随手在 `QuickNote/Quick_note_1.md` 里记了六七条：想补一下 RL 到底是什么、SDK 和 API 到底怎么区分、怀疑"模型即 Agent"和"Harness 更关键"是不是自相矛盾、希望有人把贯穿全书的设计模式再讲一遍。写得十分随便，就是卡住的地方随手记。

然后 AI 写了一份 [DeepReadNote](https://github.com/KLucen/ai-agent-book-note/tree/main/DeepReadNote)，逐条回应。举几个它真的说到点上的地方：

- **RL 的定位**：先讲清状态/动作/奖励/策略这一套，再回到书里那张控制论视角的 Agent↔Environment 闭环图。它还告诉我这个知识缺口不用现在补，第 8 章有两节可选阅读正好讲这个，到时候按需读更省力；
- **Harness 的边界**：我本来把它理解成"生产系统的完整治理层"。它指出更准确的说法是"Agent 边界内、模型之外"，而且书里的**五要素（功能职责）和三层护栏（安全纵深）不是同一套划分**，把两张图对齐时最容易在这踩坑；
- **五条设计模式**给了个口诀：**分离、按需、只增、双侧、小步**（提议者-审核者 / 渐进式披露 / 只增不改 / 边界集+保留集 / 最小 diff+可回滚）。

这大概是整份笔记里最像"讨论区"的部分：我的原始笔记一个字没改，回应放在隔壁文件，对错都摊开。

## 我给 AI 定的几条规矩

人机协作最容易出问题的地方，是最后分不清哪句话是书里说的、哪句是 AI 自己发挥的。所以：

1. **三层标注**：`〔原书〕` 书中内容 / `〔补充〕` 书外知识 / `〔精读批注〕` AI 或读者的判断；
2. **引用逐字核验 + 给出处锚点**。原书是 Markdown，没有页码，一律用「章 + 小节标题」定位，**不许编造页码**；
3. **QuickNote 是我的原文，AI 只读不改**；"我的批注"留白区 AI 不许填；
4. **思考题提示不许泄露参考答案**；
5. 若我的理解和书中结论冲突，要明确指认并给证据，不许含糊调和。

第五条是我特意加的。顺着人说的 AI 没什么用，我要的是它能说"你这条偏了，原文是这么写的"。

这些纪律本身也写在仓库里（`01-精读笔记规范.md`，现在 v2.2），想拿去写自己的精读笔记，模板可以直接抄。AI 这一侧用的是 DeepSeek Harness，也就是我现在写博客、写插件用的同一套东西。

## 一些值得注意的事情

- **第 1、2 章已精读完成**，第 1 章的 DeepReadNote 也有；**第 3–10 章只有骨架**，里面是各章主旨与大纲预览，还没填。
- 进度确实慢。一章要产出三份分册，还得真去跑实验，快不起来。好在笔记是否完整其实不重要，疑问有没有被追到闭环才重要。
- **原生是 Obsidian 笔记**，在 GitHub 上会有几处不完美：`[[内部链接]]` 点不动（得从 README 的进度表进各章）、`> [!info]` 提示框变成普通引用块、文件头的 frontmatter 渲染成一张表。想要完整体验就 clone 下来，把 `Agent Book/` 当 Obsidian 库的根目录。
- 图片是原书插图的副本（版权归原作者，依 Apache-2.0 保留署名）；笔记本体也是 Apache-2.0。
